# 業務日報システム（くるむ薬局 札幌店）

薬局の日々の業務日報を Web 画面から入力・承認し、週次の帳票（PDF）として
出力するための Google Apps Script アプリケーションです。

スプレッドシートをデータベース兼帳票テンプレートとして使い、
GAS の Web アプリ（`doGet`）が入力画面を提供します。

---

## 主な機能

- **日報入力** … 処方箋枚数・疑義照会件数・調剤室/冷所の温湿度・管理に関する事項を日ごとに記録
- **管理基準チェック** … 温湿度が基準外の場合は画面で警告し、帳票では色分け表示
- **担当者マスタ / 管理薬剤師任期** … 名簿と任期を管理し、その日の管理薬剤師を自動判定
- **押印（印影）** … 担当者印・管理者印を PNG 画像として帳票に自動配置
- **承認フロー** … 日報の承認・承認解除、編集ロック（既定 10 分で自動解除）
- **変更履歴** … 操作を監査ログとして記録
- **記録簿ビュー（監査用）** … 1か月ぶんを帳票と同じ書式で通し表示。立入検査でそのまま提示でき、PC からは画面上で直接修正も可能。印刷はサーバーを介さないので待ち時間なし
- **月次の確定** … 月が締まったら PDF に焼いてドライブに残す。訂正が出たら前の版を消さずに版を積み増す

## セットアップ

1. 対象のスプレッドシートを開き、**拡張機能 → Apps Script** を選択
2. `Code.gs` の内容をスクリプトファイルに貼り付け
3. HTML ファイル `WebApp` を新規作成し、`WebApp.html` の内容を貼り付け
4. `Code.gs` 冒頭の `CFG` を自店舗の内容に書き換え
5. 関数 `setup` を **1 回だけ** 実行（必要なシートが自動生成されます）
6. **デプロイ → 新しいデプロイ → ウェブアプリ** として公開

手順の詳細・つまずきやすい点は [SETUP.md](SETUP.md) にまとめています。

## 設定（`Code.gs` の `CFG`）

主な設定項目は以下のとおりです。ID やシート名をロジック側に直接書かず、
すべて `CFG` / `SH` / `COLS` に集約しています。

| キー | 内容 |
|---|---|
| `STORE_CODE` / `STORE_NAME` | 店舗コード・店舗名（多店舗化時はコードで日報を分離） |
| `AUTH_MODE` | `'select'`（名簿から選択・共用端末向け）/ `'google'`（Google アカウントで確定） |
| `WEEK_START` | 週の開始曜日（0=日 〜 6=土。帳票が土曜始まりのため既定は `6`） |
| `BUSINESS_HOURS` | 帳票に印字する営業時間 |
| `RANGES` | 温湿度の管理基準（`null` で基準なし扱い） |
| `LOCK_MINUTES` | 編集ロックの有効時間（分） |
| `SEAL_POLICY.ADMIN_EVERY_DAY` | 管理者印を記録・承認の有無にかかわらず毎日押すか（既定 `true`） |
| `SEAL_POLICY.REUSE_ADMIN_STAMP` | 押印済みシートを複製して使い回すか（出力の高速化。既定 `true`） |
| `PDF` | 用紙・向き・余白。ブラウザ印刷と PDF 出力の唯一の出どころ |
| `TEMPLATE` | 帳票テンプレートの行・列レイアウトと書式 |
| `SEAL_FOLDER_NAME` | 印影 PNG の保管フォルダ名 |
| `TZ` | タイムゾーン（`Asia/Tokyo`） |

`AUTH_MODE` を `'google'` にする場合、デプロイを
**「アクセスしているユーザーとして実行」** に設定する必要があります。

## シート構成

`setup()` の実行で以下のシートが自動生成されます。

| シート | 用途 |
|---|---|
| 日報DB | 日報の本体データ |
| 担当者マスタ | 氏名・メール・在籍状況・印影ファイル ID |
| 管理薬剤師任期 | 管理薬剤師の在任期間 |
| 変更履歴 | 操作の監査ログ |
| 確定台帳 | 月次を確定した記録（対象月・版・確定日時・PDFのリンク・状態） |
| 帳票テンプレート | 週次帳票の雛形（`buildTemplate()` で生成） |

## トリガー

このアプリは **常設のトリガーを使用しません**。すべての処理は
Web アプリからの `google.script.run` 呼び出し、またはエディタからの手動実行です。

ただし、長期間の PDF 出力（`startExport`）は 6 分の実行時間制限を避けるため、
`runExportChunk` を分割実行する方式をとっています。

## 画面の構成

トップバー右側の丸ボタンで画面を切り替えます。選んだ画面だけを表示し、他は隠します。

| ボタン | 画面 | 内容 |
|---|---|---|
| 入力 | 日々の入力 | 本日の状態・週の一覧・入力もれ・入力フォーム |
| 記録簿 | 監査用の記録簿 | 1か月ぶんを帳票と同じ書式で通し表示。直接修正も可能 |
| 確定簿 | 確定した月の一覧 | 月ごとに版が並ぶ。監査ではここから PDF を開きます |
| 名簿 | 担当者の管理 | 名簿・管理薬剤師の任期・変更履歴（モーダル） |

書きかけの内容があるまま別の画面へ移ろうとすると確認を求めます。記録簿に未保存の行が
あるときは、記録簿ボタンに目印が付きます。

## 記録簿ビュー（監査用）

トップバーの「記録簿」ボタンから開きます。1か月ぶんを帳票テンプレートと同じ書式で
週ごとに並べるため、**画面の1枚が印刷の1ページ**にそのまま対応します。

- 上部に「対象日数 / 記録あり / 承認済み / 未記録 / 基準逸脱」の集計を表示します
- 管理基準を外れた日は、日付と実測値を一覧で示します
- 既定は**閲覧専用**です。「編集」を押したときだけ値を直せます（画面の色が変わります）
- 印刷は2通りあります（下記）

### 記録は「データ」、確定した月は「PDF」

日々の帳票は**データから毎回描き直します**。画面（記録簿ビュー）がそのまま印刷され、
サーバーへは行かないので待ち時間がありません。

ただしそれだけだと、あとから印影を差し替えたりテンプレートの列幅を変えたりしたときに、
**過去の帳票の見た目まで変わってしまいます**。監査で「これは当時のものです」と言えなく
なるため、月が締まった時点で1回だけ PDF に焼き、それを残します。

| | 実体 | 使う場面 |
|---|---|---|
| 確定前 | データから毎回生成 | 日々の確認、監査での画面提示、訂正 |
| 確定後 | その時点の PDF | 「承認時点でこうだった」の証明 |

出力の入口は2つだけです。

| ボタン | 通る道 | 速さ | 出力先 |
|---|---|---|---|
| 記録簿「印刷」 | `printPaper_()` | **即座**（サーバー往復なし） | プリンタ／ブラウザの「PDFに保存」 |
| 記録簿「この月を確定」 | `startJob_({ fn:'startFreeze' })` | 1週あたり数秒。**月に1回だけ** | ドライブの「業務日報_出力／&lt;年&gt;」 |

用紙・向き・余白は `CFG.PDF` が唯一の出どころです。起動時に画面へ渡し、
ブラウザ印刷の `@page` と縮小率にも同じ値を当てるので、**2つの経路で
刷り上がりが食い違いません**。`CFG.PDF.MARGIN_IN` を変えれば両方が追従します。

画面のプレビューと刷り上がりがずれないよう、次を揃えています。

- 書体は帳票（スプレッドシート）側に合わせた `Arial` 系
- A4 横・1週 = 1ページ
- 紙に入る幅を実測し、はみ出す分だけ縮小（帳票 1071px に対し A4 横は約 1062px なので、ほぼ原寸）
- 画面用の色分け（未記録・承認済・未保存）や操作ボタンは紙に出しません

### 月次の確定

記録簿で月を開くと、その月の状態が上部に出ます。

```
まだ確定できません
  ・その月がまだ終わっていません
  ・未記録が 3 日あります
  ・未承認が 1 日あります
```

**確定できるのは、月が終わっていて、未記録が無く、全日が承認済みのときだけ**です。
条件がそろうと［この月を確定］が押せるようになり、PDF がドライブに残ります。

```
業務日報_出力/
  2026/
    2026-08_業務日報_v1_確定20260901.pdf
    2026-08_業務日報_v2_確定20260915.pdf   ← 8/12を訂正して作り直した
```

#### 訂正が出たとき

上書きはしません。上書きすると訂正の痕跡が消え、監査証跡としての価値がなくなります。

1. 記録簿で承認を解除して直す（`変更履歴` に「何をどう直したか」が残ります）
2. もう一度承認する
3. ［確定を作り直す］を押し、**理由を書く**（理由も台帳に残ります）
4. 第2版として積み増す。第1版はそのまま残ります

`変更履歴` と `確定台帳` が対応するので、「v1 と v2 の違いは？」と聞かれたら履歴を出せます。

#### 誤って確定したとき

［取り消す］で **取消** にできます。PDF もドライブの記録も**消しません**。
消してしまうと「間違えて出した」という事実まで消えてしまうためです。
取り消した版の番号は再利用しません（v2 を取り消しても、次は v3）。

### 確定簿ビュー

トップバーの「確定簿」から開きます。確定した月が新しい順に並び、
各月の最新版へのリンクと、過去の版・取り消した版が下に残ります。
監査で「去年の8月を見せて」と言われたときは、ここから開きます。

### 確定にかかる時間と、その進み具合

長い期間だと数十分かかることがあるため、進み具合は**画面下に固定した帯**に出します。
スクロールしても、ほかの画面へ移っても見えたままです。残り時間はそのジョブの実測から、
まだ0週なら前回までの実績から見積もります。

出力時間のほとんどは**印影の貼り付け**です。1枚ずつシートと往復するうえ、保留していた
書き込みをその場で反映させてしまうため、素直に書くと1週あたり14枚ぶんの往復と、
日数ぶんに分断された書き込みが発生します。次の手当てが入っています。

| 手当て | 内容 |
|---|---|
| 値と印影を分ける | 値をぜんぶ書いて1回で反映させてから、印影を貼る |
| 列のまとまりごとに書く | セルを1つずつではなく `setValues` でまとめる。1週 80回 → 36回 |
| 押印済みシートの使い回し | `SEAL_POLICY.REUSE_ADMIN_STAMP`。押す位置は曜日で決まるので、同じ並びの週は複製で引き継ぐ |

管理者印は記録の有無によらず毎日押されるので、**管理薬剤師の交代日をまたがない限り、
どの週も並びが同じ**です。任期のあいだは押し終えたシート1枚を使い回せます。
交代をまたぐ週だけは並びが変わるため、その週は1コマずつ押します。

複製で画像が引き継がれるかは環境しだいなので、**最初に1枚だけ押して確かめ、駄目なら
1コマずつ押す方式へ自動で戻ります**。どこに時間がかかっているかは
**`benchmarkExport`** で測れます（複製・値の書き込み・印影に分けて実行ログに出ます）。

確定は月に1回なので、ここが多少遅くても日常の運用には影響しません。
日々の印刷はサーバーを介さないため、待ち時間はゼロです。

### 承認済みの日を直したとき

内容が変わった記録に、前の内容に対する承認印を残すことはできません。そのため
承認済みの日を修正すると、次の2つが必ず行われます。

1. 変更前後の値を「変更履歴」シートに記録する
2. 承認を解除して「入力済」に戻す（管理薬剤師の再承認が必要になる）

画面側でも保存前に確認を求めます。

### 担当者の扱い

既に記録がある日は、その日の担当者を勝手に書き換えません。修正した人は
変更履歴の「操作者」に残ります。別の人の勤務日をあとから入力する場合は、
編集中に担当者印の欄で担当者を選び直してください。

## 困ったとき

### PDFの四隅（外枠）が欠ける

帳票は **1071px = 283.4mm** あり、A4横・余白0.4インチで印刷できる幅は **276.7mm** です。
はみ出すぶんを `fitw` が 97.6% に縮めるため、**縮小後の帳票の幅が印刷できる幅と
完全に一致**します。いちばん外側の罫線が切り取り線の真上に来るため、削られて
四隅が欠けて見えます。

対策として次を入れてあります。

- 出力する各週の**外枠を少し太く**しておき、削られても残るようにした
- **原寸で収まるときは縮小しない**（余白ができるので外枠が切り取り線に触れない）

それでも気になる場合は、スクリプトエディタで **`checkPrintFit` を実行**してください。
実寸・印刷できる範囲・縮小率が実行ログに出ます。そのうえで、どちらかを。

| 方法 | やり方 |
|---|---|
| 余白を詰める | `CFG.PDF.MARGIN_IN` を `0.4` → `0.2` に。**原寸出力に切り替わります** |
| 帳票を詰める | 帳票テンプレートの列幅を合計 32px ぶん狭める（`F` 列に余裕あり） |

> `CFG.PDF` で用紙・向き・余白を変えられます。判定は自動で追従します。

なお **記録簿の「印刷」（ブラウザ印刷）はこの問題が起きません**。スプレッドシートの
PDF書き出しを経由しないためです。


### 入力したのに、値が保存されていない

シートに**その列が無い**可能性があります。シートへの書き込みは見出し行にある列だけを
対象にしているため、`COLS` に項目を足したあと古いシートを使い続けると、その項目は
保存されません。

スクリプトエディタで **`checkSheets` を1回実行**してください。足りない列を検出して
その場で追加し、実行ログに結果を出します。追加した事実は「変更履歴」シートにも残ります。

現在は読み書きの前に自動で列をそろえるため、この状態は起きません。見出しに無い項目を
書こうとした場合もエラーになり、黙って捨てられることはありません。

> 自動追加された列は、シートのいちばん右に付きます。並び順が `COLS` と違っても
> 動作には影響しません（すべて見出し名で読み書きしているため）。

## 取り扱い上の注意

- 印影 PNG を保管するフォルダ（既定名 `業務日報_印影`）は **誰とも共有しないでください**。
- 担当者の氏名・メールアドレスはスプレッドシート側で管理します。
  リポジトリには個人情報を含めないでください。
- スプレッドシート ID や共有 URL をコードに直書きしないでください。
